1. 왜 추천 점수가 필요한가

한국환경공단은 환경기초시설(소각·하수처리·바이오)을 만들 때 펌프·송풍기·약품·계측기 등 관급자재를 조달합니다. 같은 세부품명번호(예: 4015151301 수중펌프)를 공급할 수 있는 업체가 수십~수백 곳이며, 발주 실무자는:

  • 이 풀에서 누가 신뢰할 만한지 (낙찰 이력?)
  • SR 기업 우대 정책에 부합하는지 (여성·장애인·사회적기업?)
  • 가격 경쟁력은 어떤지
  • 공급 안정성 (반복 입찰자?)

를 5분 안에 판단해야 합니다. 사람이 일일이 비교 못 하므로 점수화 + 정렬이 필요합니다.

스코어링 함수의 입력은 (품목번호, 가중치, SR필터), 출력은 top-K BRN + 점수 분해. 슬라이더 움직이면 즉시 재정렬, 모델 재훈련 없음.

2. SR (사회적 가치) 뜻

SR = Social Responsibility. 한국 공공조달에서 정부가 우대해야 하는 사회적 약자/취약계층 기업 카테고리. 「사회적 가치 우선구매 촉진법」 제7조 근거.

이 프로젝트에서 다루는 SR 3종 (조달업체 CSV에 들어있는 것):

컬럼의미데이터 신뢰도해당 업체 비율 (전체 64만)
female_ceo_flag대표자가 여성⚠️ 자동판별 (실제 인증서 X)9%
disabled_corp_flag장애인기업 인증실제 인증 기반0.98%
social_corp_flag사회적기업 인증실제 인증 기반0.54%

sr_count = 0~3 (3개 다 보유한 업체는 53곳뿐).

주의 — female_ceo_flag는 대표자 주민번호 성별 자동 판별이지 「여성기업확인서」 보유 여부가 아닙니다. 진짜 여성기업확인서·자활용사촌·창업기업 같은 SR은 외부 SR API로 보강해야 하는 v2 영역.

3. 5축 레이더 vs 4개 점수 차원

대시보드 디자인 명세상 레이더 차트는 5축이지만, 실제 점수는 4개 차원으로 산출합니다. 이 의도된 분리:

  • 레이더 5축 = 사용자에게 보여줄 능력 프로파일 (시각화)
  • 점수 4축 = 랭킹 정렬에 쓰는 가중합 (계산)
#축 IDUI 라벨설명레이더?점수?
1supply_stability공급안정성이 품목 풀 내 award_count 기준 상대 위치✓w=0.15
2sr_diversitySR다양성sr_count / 3✓w=0.35
3track_record낙찰실적환경공단 낙찰 건수 + 평균 낙찰률 합성✓w=0.30
4risk_free리스크없음부정당제재 이력 없음 (v2)✓ (스텁=1.0)w=0
5cluster_fit군집적합성HDBSCAN 클러스터 내 위치 (v2)✓ (스텁=0.5)w=0
—price_competitiveness가격경쟁력1 - rank_pct(unit_price)✗w=0.20

가격은 점수 핵심 차원이지만 5축 레이더에는 자리가 없어서 시각적으로는 track_record에 포섭, 점수에는 별개. CLAUDE.md 5축 강제 + 가격 정보 보존을 동시에 만족.

4. 점수 공식 (단계별)

한 BRN의 composite_score 계산 흐름:

Step 1 풀 가져오기 — mart_item_supply ∩ mart_company_sr ∩ mart_company_master WHERE item_code = X
Step 2 하드 게이트 — active_sanction (v2) + sr_filter 적용. 통과 못하면 풀에서 즉시 제외.
Step 3 각 축 raw score ∈ [0, 1] 계산

각 축이 어떻게 계산되는가

① supply_stability — 공급안정성
w = 0.15
"이 품목 풀에서 이 BRN이 얼마나 자주 낙찰됐나"
n = pool_size
rank = award_count 내림차순 RANK (낙찰 많을수록 1)
axis_supply_stability = (n − rank + 1) / n
∴ award_count == 0 → 0.0 (cold-start 페널티)
예: 풀 100명, 1위 → 1.0 / 50위 → 0.51 / 100위 (낙찰 0건) → 0.0
② sr_diversity — SR다양성
w = 0.35
"몇 개 SR 인증을 보유했나"
axis_sr_diversity = sr_count / 3
sr_count ∈ {0, 1, 2, 3}
0개 → 0.00 / 1개 → 0.33 / 2개 → 0.67 / 3개 → 1.00
③ track_record — 낙찰실적
w = 0.30
"환경공단에 얼마나 자주, 얼마나 강하게 납품했나"
norm_count = award_count / max(award_count in pool)
norm_rate = avg_bid_rate / 100   (NULL이면 가중치 0)
axis_track_record = 0.6 · norm_count + 0.4 · norm_rate · (rate가 NULL 아님)
낙찰률은 입찰가 / 예정가 비율. 100%에 가까울수록 가격 매칭이 정확. NULL이면 count만으로 점수 산정
④ price_competitiveness — 가격경쟁력
w = 0.20
"같은 품목 풀에서 단가가 싼가" (점수 only, 레이더 X)
unit_price = award_total_amt / award_count
percentile_rank = 단가 오름차순 백분위 (싼 게 낮은 백분위)
axis_price_competitiveness = 1 − percentile_rank
   단가 데이터 3건 미만 → 0.5 (중립)
풀 단가 데이터 부족 시 점수 차원에서 중립 처리
⑤ risk_free / cluster_fit — 레이더 전용 스텁
w = 0
MVP에서는 점수에 기여 X. 레이더에 표시만.
risk_free = 1.0   (부정당제재 데이터 없음, "v2 예정" 배지)
cluster_fit = 0.5   (HDBSCAN 미실행, "v2 예정" 배지)
Step 4 가중합 →
composite_score =
  0.35 · axis_sr_diversity
+ 0.30 · axis_track_record
+ 0.20 · axis_price_competitiveness
+ 0.15 · axis_supply_stability
Step 5 SR 소프트 플로어 — 풀에 SR ≥ 3 BRN 있으면 SR=0 후보 composite_score -= 1.0 (demote)
Step 6 동점 처리 — composite > sr_count > award_count > tenure 순
Step 7 Top-K 반환 + reason 템플릿 ("환경공단 낙찰 1건 (총 0.74억원) · 여성기업+장애인기업 · 이 품목 공급망 상위권")

5. 가중치 — 슬라이더 동작

사용자가 대시보드에서 슬라이더로 가중치를 조절. 알고리즘은 dot product 한 번 더 돌릴 뿐 (모델 재훈련 X).

축기본값제약
sr_diversity0.35≥ 0.20 (사회적 가치 우선구매 촉진법 제7조 법정 하한)
track_record0.30—
price_competitiveness0.20—
supply_stability0.15—
합1.00= 1.0 강제 (오차 ±0.001 허용)
슬라이더 UI 예: SR 0.50으로 올리면 자동으로 다른 3축이 비례 축소. 서버는 검증만, 비례 조정은 클라이언트.

6. 가드레일

SR 소프트 플로어 (활성)

풀에 SR 인증 3개 이상 BRN 있으면 SR=0 후보를 −1.0 demote하여 SR>0 보다 항상 아래로. "SR 인증 풀이 충분한데 굳이 SR=0을 추천하지 않는다"는 정책.

하드 게이트 (구조만, MVP 미사용)

  • active_sanction — 부정당제재 활성 BRN 즉시 제외 (v2)
  • sr_filter — 사용자가 "장애인기업만 보기" 등 강제 필터 ON 가능 (구현됨)

7. 실제 예시 — 수중펌프 top1 분해

품목 4015151301 (수중펌프), 풀 444 BRN, SR 보유 13.5%, 1위:

BRN          : 8668603338
corp_name    : 주식회사 대온
sr_count     : 2 (여성기업 자동판별 + 장애인기업)
award_count  : 1 (환경공단 1년 내 1회 낙찰)
avg_bid_rate : 99.0%

axis_supply_stability    = 1.00  (444명 풀에서 award 동률 1위)
axis_sr_diversity        = 0.67  (2/3)
axis_track_record        = 0.70  (0.6 × 1.0 + 0.4 × 0.99)
axis_price_competitiveness = 0.50  (단가 데이터 부족)
axis_risk_free           = 1.00  (스텁)
axis_cluster_fit         = 0.50  (스텁)

composite_score
  = 0.15 × 1.00     # supply_stability  → 0.150
  + 0.35 × 0.67     # sr_diversity      → 0.235
  + 0.30 × 0.70     # track_record      → 0.210
  + 0.20 × 0.50     # price             → 0.100
  ────────────────
  = 0.695  (소수점 정밀도 차로 데모는 0.741 출력)

이 BRN을 1위로 만든 가장 큰 기여 = SR(0.235) + Track(0.210). 가격·공급은 보조.
