1. 전체 워크플로우

발주 공고 이전에 담당자가 품목·정책 필터·예산을 입력하면, 시스템은 후보 BRN(사업자등록번호) 풀에서 top-K 추천을 반환한다. 내부 처리는 4단계로 분리된다.

각 단계 상세

  • Stage 1 — Retrieve: 키워드 8개(pipeline/item_keywords.py)를 prefix4 코드 집합과 정규식으로 변환해 후보 풀을 좁힌다. 정책 필터(사회적기업/여성기업/장애인기업)는 hard filter로 작용한다.
  • Stage 2 — Rank: RuleRanker가 후보별 4축 점수를 계산해 가중합한 뒤, SR floor·클러스터 보정을 적용한다. Stage 2는 향후 LGBMRanker로 1:1 교체 가능하도록 Ranker Protocol 인터페이스로 분리되어 있다.
  • Enrich: rank 상위 BRN에 대해 예상가격(시장 분위수), 리스크 등급, 최근 낙찰 이력, 유사 발주 사례, K-NN 유사 BRN 시그널을 DB에서 조회해 카드로 조립한다.
학습 기반 ML 모델(LGBM Classifier, AUC 0.858)은 학습돼 있으나 사전탐색 모드에는 사용되지 않는다. 사전탐색 모드는 공고 입력이 없어 (공고, BRN) 쌍 피처를 만들 수 없기 때문이다.

2. 클러스터 5 그룹

1,694개 활성 BRN을 15차원 피처(낙찰 건수·평균 낙찰률·SR 보유 수·활동 최근성·prefix4 다양성 등)로 UMAP 임베딩(5D) → HDBSCAN 군집화한 결과 12개 군집과 노이즈(2.95%)가 나왔다. 12개 군집은 운영 의미 단위로 다시 5 그룹으로 묶었다(pipeline/cluster_groups.py).

그룹 의미 시그널 가중치 보정
veteran 환경공단 주력 낙찰 건수 많음 + 최근 활동 + prefix4 다양(여러 품목 공급 가능) + 가산 (살짝)
real_sr 진짜 SR 인증 보유 사회적기업·장애인기업 등 외부 인증서 기반 SR + 가산 (살짝)
auto_sr 자동판별 SR 여성기업처럼 대표자 성별로 자동 부여. 인증서 없음 0 (중립)
dormant 휴면 최근 24개월 무낙찰. 활동 중단 가능성 − 감산 (살짝)
noise 미할당 HDBSCAN이 어느 군집에도 못 넣은 BRN (1,694 중 50개) 0 (중립)

왜 12군집을 5 그룹으로 묶었나

12군집 그대로 코드 분기에 쓰면 12-way switch가 되고, 한국어 라벨이 한 단어만 바뀌어도 분기가 조용히 깨진다(Hyrum's Law). 5 그룹은 활동성 × SR 진위 축의 운영 의미만 추린 것이다. 라벨 문구와 분리된 enum이라 라벨이 바뀌어도 동작은 유지된다.

핵심 구분: real_sr vs auto_sr

  • real_sr: 사회적기업·장애인기업은 외부 기관 인증서가 있어야 보유로 인정된다.
  • auto_sr: 여성기업 인증여부는 조달업체 CSV에서 대표자 성별로 자동 Y/N이 매겨진다. 진짜 인증이 아니다.

두 부류는 같은 sr_count = 1이라도 행동 패턴이 달라, 클러스터링이 자연스럽게 분리한다. 가중치 보정에서도 real_sr만 가산을 받고 auto_sr는 중립이다.

한계

12군집을 사후 분석한 결과 (prefix4 × 휴면 여부 × SR 종류)의 카르테시안 곱과 거의 일치한다. 비지도 학습이 추가로 발견한 구조라기보다 기존 도메인 분류의 재확인에 가깝다. 따라서 운영 카드의 표층 표기에서는 제외하고, 백엔드 점수 보정의 작은 신호로만 사용한다.

3. 점수 산출 (휴리스틱 룰)

운영 카드 점수는 학습 모델이 아닌 휴리스틱 룰이다. RuleRanker가 4축 점수를 가중합한 뒤 두 단계 보정을 적용한다.

3.1 4축 가중합

축 가중치 측정 대상 정규화
SR 다양성 0.35 이 BRN이 보유한 SR 인증 수 (사회적+여성+장애인 중) 후보 풀 내 min-max → 0~1
실적 0.30 환경공단 과거 낙찰 건수 + 최근성 후보 풀 내 min-max → 0~1
가격경쟁력 0.20 평균 낙찰률(낮을수록 가산) 역방향 min-max → 0~1
공급안정성 0.15 G2B 등록 기간, 제조업 여부, 활동 지속성 후보 풀 내 min-max → 0~1 
raw = 0.35 × sr + 0.30 × track + 0.20 × price + 0.15 × supply

3.2 보정 ① — SR floor demote

후보 풀에 SR 보유 BRN이 3명 이상인데 본인은 SR 0개인 경우, raw에서 1.0을 차감한다. raw 범위가 0~1이므로 음수가 되어 정렬상 사실상 꼴찌가 된다. 정책 의무비율 보장 장치다.

3.3 보정 ② — 클러스터 보정

위 5 그룹 enum에 따라 raw에 ±0.05 안팎의 작은 보정을 더한다. 합이 1.0을 벗어나면 다시 정규화하되, SR floor가 깨지면 한 번 더 재조정한다.

3.4 등급 (tier)

최종 점수를 상위 ~33% / 중위 / 하위로 나눠 A (강추) / B (추천) / C (검토)로 표기한다. raw probability나 점수 자체는 운영 카드에 노출하지 않는다(calibration 부재).

3.5 예시 — 펌프, 후보 5명 중 상위 2

한마음 (낙찰 14, SR 3개, 평균 낙찰률 87%)
  sr 1.00 × 0.35 + track 0.95 × 0.30 + price 0.50 × 0.20 + supply 0.95 × 0.15
  = 0.35 + 0.285 + 0.10 + 0.1425 = 0.88   → 1위 · A

신한 (낙찰 6, SR 0개, 평균 낙찰률 86%)
  raw 0.45 (4축 가중합)
  → SR floor demote 발동 (-1.0)
  → 최종 -0.55                              → 5위 · C

4. 가중치·보정 값의 근거

모든 숫자는 휴리스틱이다. 데이터로 학습하거나 calibration을 수행한 부분은 없다. 다만 각 magnitude는 다음 의도를 따른다.

대상 설계 의도 (사후 정당화)
축 순서 (SR > 실적 > 가격 > 공급) 시스템 존재 이유가 사회적 가치 의무비율이므로 SR이 1순위. 환경공단 경험은 안전 신호, 가격은 변동성이 커서 비중을 낮춤, 공급안정성은 변별력이 가장 약함.
SR floor demote −1.0 raw 범위가 0~1이므로 −1.0이면 무조건 음수 → 정렬상 항상 꼴찌. −0.5 같은 약한 값을 쓰면 다른 축이 강한 SR 0 BRN이 SR 보유자보다 위로 올라와 정책 의무가 깨진다. 본질은 magnitude가 아니라 "충분히 큰 음수"라는 조건.
클러스터 보정 ±0.05 raw 0~1의 약 5%. tier 경계 근처에서만 영향이 있고 압도적 1위는 흔들지 않는 크기다. ±0.2 수준이면 클러스터가 4축 자체를 뒤집고, ±0.005이면 의미가 없다.

검증의 부재

  • 운영 피드백 라벨(좋은 추천 / 나쁜 추천)이 없어 가중치 학습은 불가능하다.
  • A/B 테스트는 수행되지 않았다.
  • "왜 0.35이고 0.40이 아닌가"에 대한 답은 없다. 답할 수 있는 것은 순서뿐이다.

대체 가능성

Stage 2의 RuleRanker는 Ranker Protocol로 분리돼 있어 LGBMRanker(현재 학습은 됐으나 미사용)로 1:1 교체 가능하다. 운영 피드백 로그가 쌓이면 가중치 학습이나 ranker 자체 교체가 가능한 구조다.
