지금 뭘 하려는 건가

한국환경공단 환경기초시설 관급자재 SR 공급망 분석 — 2026-05-05 현재 상황

한 줄로

환경공단이 어떤 자재를 발주할 때, "어느 회사를 추천할지"를 과거 5년치 입찰 데이터로 학습한 모델이 실무자에게 제안해준다. 그 추천이 SR(사회적 가치) 정책도 함께 만족하는지 옆에 같이 보여주는 시스템이다.

왜 만드는가

지금 발주 실무자가 겪는 문제

  • 같은 품목(예: 수중펌프)을 공급할 수 있는 회사가 수십~수백 곳
  • 그 중 어느 회사가 환경공단 발주에 적합한지 판단할 데이터가 분산돼있음
  • SR 정책도 만족시켜야 함 — 여성·장애인·사회적기업 비율 의무
  • 결정 근거를 한눈에 모은 도구가 없음

이 프로젝트가 답하려는 질문

"이 발주 공고에 가장 적합한 회사 5곳은 어디고, 그 이유는 무엇인가?"

실무자가 5분 안에 의사결정을 내릴 수 있는 추천 도구를 만드는 게 목표.

어떻게 만들 건가 — 4단계

[1단계] 데이터 수집 └─ 조달청 OpenAPI 4개 + 조달업체 CSV ├─ 입찰공고 (어떤 발주가 떴나) ├─ 개찰결과 (1순위·유찰·재시담) ├─ 최종 낙찰자 (Y 라벨) └─ 복수예가 (가격 분포) [2단계] 피처 만들기 └─ (공고, 회사) 페어마다 숫자 30여 개 ├─ 회사 특성 (규모·업력·SR 인증) ├─ 회사의 과거 환경공단 활동 ├─ 공고 정보 (품목·가격·권역) └─ 시장 구조 (그 품목 경쟁도) [3단계] 모델 학습 └─ "이 회사가 이 공고 최종 낙찰자였나? Y/N" 이진 분류로 학습 → 추천 랭킹 산출 [4단계] 대시보드 + 피드백 └─ 실무자가 품목·예산·SR 조건 입력 → 상위 5곳 추천 + 근거 + 가격 + 위험도

예정

모델이 답하는 질문 (구체화)

입력 (실무자가 주는 것)

  • 품목 — 예: 수중펌프, 대기오염측정기
  • 예산 — 추정가격
  • SR 조건 — 사회적기업 / 장애인기업 (선택)

출력 (모델이 주는 것)

  • 추천 회사 Top 5 — 점수 순서
  • 각 회사별 근거
    • 환경공단 과거 낙찰 횟수·금액
    • 같은 품목 경험
    • SR 인증 여부
    • 예상 가격대
    • 최근 활동 시그널
  • 위험 신호
    • vendor lock-in 의심 (한 회사 독점)
    • 1순위 자주 떨어짐 (덤핑 의심)
    • 유찰 빈번 품목 (공급망 부족)

지금까지 데이터로 알게 된 5가지 사실

발견의미
환경공단 입찰 12.9%가 유찰
(권역별 4.6% ~ 17.7% 편차)		 특정 권역의 특정 품목은 공급사 풀이 얇음
→ 추천 시 SR 조건 완화 가능성 안내 필요
1순위 회사 5.7%는 최종 탈락 덤핑·적격심사 탈락 패턴
→ 그런 회사는 추천 점수 낮춰야 함
6개 품목은 vendor lock-in 의심
(한 회사가 50% 이상 점유)		 모델이 그대로 학습하면 같은 회사만 추천
→ "경쟁 부재 경고" 표시 필요
자주 낙찰받는 회사 = 제조업 80%, 실질 SR 11%, 평균 업력 15년 "제조업 + 오래된 + 진짜 SR" 트리오가 강한 신호
"환경공단 낙찰 0건"이지만 입찰 활동은 있는 회사 428곳
(그 중 SR 보유 다수)		 지금까지 noise 취급되던 SR 업체 다수
→ 모델이 살려낼 후보

모델이 가져야 할 안전장치

위험 1 — Heavy winner 편향
환경공단 낙찰 4건 이상인 회사는 46곳뿐. 모델이 정확도만 높이면 항상 그 46곳만 1위로 추천 → SR 영구 누락.
방지: 평가 지표에 SR Coverage @ 5 (상위 5개 추천 중 SR 비율) 포함.
위험 2 — 가격 정보 누설
9번 API의 복수예가 정보(plnprc 등)는 개찰 후 확정되는 값. 학습 시점엔 모르는 미래 정보.
방지: 가격 피처는 공고일 기준으로만 (presmpt_prce = 추정가격만 사용).
안전장치 3 — Calibrated 확률
추천 점수가 "73%"면 실제로 73% 확률로 낙찰돼야 함. 그래야 실무자가 의미를 이해할 수 있음.
적용: Platt scaling 또는 isotonic regression.

이번 주 목표

  1. 피처 빌더 코드 작성 (point-in-time, leakage 0)
  2. 학습 데이터 export (~10만 행)
  3. LightGBM baseline 학습 + 평가
  4. 모델 결과를 기존 React 대시보드에 연결

9번 가격 피처는 leakage 위험으로 단순화 / 부정당제재 API는 보류 (등록명 미확인).
